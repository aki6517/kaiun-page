# 鑑定書プロンプト設計（型の正本）

作成: 2026-08-26（せお）／素材: Google Drive上の実物鑑定書5通（「〇〇様.pdf」・旧shiva名義・2022年作成群。個人情報のため本ドキュメントには氏名・原文の長文引用は載せない）

## 実物から抽出した「型」（セクション構成）

1. **表題＋宛名**: 「鑑定書」＋「〇〇様」。本文中でも「〇〇様は…」と名前で繰り返し呼びかける（パーソナル感の核）
2. **本質・性格**: 肯定ファースト。強みを具体的に2〜3個→弱みは1個だけ、「〜な面があります」と優しく指摘し、必ず対処アドバイスとセットにする（例: 「決断し行動することを意識しましょう」）
3. **金運（★1〜5）**: 星評価＋解説。実物は★1の正直な回答もあるが、必ず「どうすれば良くなるか」で締める
4. **年運**: 今年・来年の2年分。「種まき→芽吹き→開花」のような自然のメタファーで周期を説明
5. **あなたを癒す言葉**: 1フレーズ（鍵括弧）＋なぜその言葉かの解説。自分軸への促し（例系統: 「私を幸せにできるのは私ただ一人」）
6. **開運アイテム**: 「目に見えないエネルギー」の枕→ ●カラー ●パワーフード ●アイテム ●ラッキースポット ●開運行動（バリエーション: ●霊数 ●方角）
7. **結び**: 「〇〇様の人生がより良い方向に進んでいけますよう、いつも応援しております」＋署名

## 文体ルール（実物準拠）

- 1文が短い。2〜4行で改行するリズム（スマホ読み前提）
- 「です・ます」の柔らかい敬体。命令形は使わず「〜しましょう」「〜してください」
- 抽象語で逃げず、行動レベルの具体（服装・食べ物・場所・行動）まで落とす
- 弱み・低運気も見放さない。「充電期」「準備期間」と意味づけて、その期間に合う行動を渡す

## ルナ版へのアレンジ（新規設計）

- **署名 = 紗々・マグダレナ**（旧shivaは使わない）。結び例: 「〜 紗々・マグダレナより愛を込めて 〜」
- **AI開示を鑑定書内に明記**: 末尾に「本鑑定はAI鑑定システムが生成しています（紗々・マグダレナ監修）」
- **月と暦の要素を追加**: ルナブランドとの接続として、生年月日から「あなたの月リズム」（新月生まれ寄り/満月生まれ寄り等の切り口）を1セクション入れる。データは `lib/kaiun-days-2026.ts` 系の裏取り済みデータのみ使用
- **安心設計3ヶ条によるNG調整**（実物からの変更点）:
  - 「財布を落とす・盗まれる」等の具体的不幸予告 → 禁止。「お金の管理を丁寧にすると安心な時期」等の行動アドバイスに変換
  - 「運気が低迷します」→「充電の2年間」等、期間の意味づけ＋その期間の推奨行動に変換
  - 断定的未来予測（必ず/絶対）・医療/法律/投資助言 → 禁止
  - 偽の限定性・課金を煽る文言 → 禁止（有料版の案内は事実だけ淡々と）

## 無料版／有料版の切り分け（¥2,000）

| | 無料簡易鑑定 | 有料詳細鑑定書 ¥2,000 |
|---|---|---|
| 本質・性格 | ダイジェスト（強み2つ＋ひとこと） | フル（強み・弱み・対処まで） |
| あなたを癒す言葉 | ○（フックとして強い） | ○ |
| 今年の運勢 | 3〜4文のダイジェスト | フル＋来年の運勢 |
| 恋愛運・金運・仕事運・人間関係 | ✗（ぼかし表示の対象） | ★評価＋各フル解説 |
| 月リズム | ✗ | ○ |
| 開運アイテム | ✗ | ○（カラー/フード/スポット/行動） |

- 無料版だけでも「もらって嬉しい」完成度にする（配り損にしない＝リストの信頼が資産）
- ぼかし部分の見出しと★評価だけは見せてもよい（中身のテキストはHTML非送出、計画正本参照）

## 実装メモ（2026-09-03改訂: 生成AI = Claude Code headless／ローカルワーカー）

- **生成はGemini APIでなくClaude Code（`claude -p`・サブスク内）**。ワーカー（`~/dev/luna-kantei-worker/`）がこのドキュメントを型の正本として読み込み、申込み1件ごとに鑑定書を生成する
- 出力形式: JSON固定（free{essence, healing_word, this_year_digest} / paid{love, money, work, relationships, next_year, moon_rhythm, items}）。ワーカー側でスキーマ検証し、不正なら1回リトライ
- 入力: 名前（呼びかけ用・姓名どちらでも）・生年月日・生成日
- 占術ロジック（九星/数秘等）はプロンプト内で厳密計算させない。「生年月日から導かれる傾向」として叙述させ、暦データ（新月満月等）だけ実データを注入する
- 禁止語リスト（出力後チェック用）: 必ず/絶対/危険/警告/このままだと/今だけ/残り○名/盗まれる/失う 等 — 実装時に確定
- 敬体固定・名前の呼びかけ回数min指定（パーソナル感の担保）
